# cis-lab 画布编辑实测

2026 年 11 月 20 日至 21 日，九个 VibeEdit 案例在 cis-lab 的同一张 RTX 4090 上生成。系统首轮验收通过 3 例，允许最多三次生成后累计通过 5 例。逐图对照作者参考后，我在五个放行结果中发现一例误放行。以下事后判断由 Codex 完成，人工判定栏保持空白，供独立复核。[输入清单](cases.json) · [机器记录](batch-summary.json) · [逐图对照页生成脚本](review.py) · [VibeEdit 作者图库](https://zhaojingjing713.github.io/VibeEdit/)

## 校准与浏览器

四个既有候选的盲验收均符合预期。验收拒绝了删错靠垫、主体正确但留有红字的蕨类、下层原位仍有摆件的候选，放行了正确的耳罩改色。校准初试有两个视觉调用触发超时。使用中等推理强度并按整行框选残留文字后重新执行，四例均取得结构化结果。[四例校准记录](calibration/summary.json)

浏览器实测从上传干净原图开始，使用画笔、箭头和撤销，再圈选目标并写上指令。行李箱案例刷新页面后恢复同一任务，首轮通过，下载的 PNG 与任务候选逐字节一致。另一条蓝椅任务验证了服务错误恢复、从干净原图裁剪重做，以及次数耗尽后下载未通过的最佳候选。两次下载验证均未记录浏览器脚本错误。[行李箱实测](browser-suitcase/verification-summary.json) · [蓝椅实测](browser/verification-summary.json)

蓝椅首次读图时，本机网页用户服务缺少 Codex 出站代理，尚未提交 Qwen。配置修正后，浏览器从原任务 ID 继续。另用一张无笔迹、无文字说明的椅子图运行单图命令，系统询问需要编辑的对象与操作，生成次数为零。

校园网部署后，从 cis-lab 以外的机器再次上传原图、圈选、提交、刷新并下载。该次行李箱任务三轮后仍未通过，最佳候选中的岩石纹理发生变化。校园网页准确显示此状态，下载内容与该候选逐字节一致。复核页的九组共 36 个图像面板均可打开，浏览器能导出复核记录。这些额外的浏览器运行独立于上表九例统计。[校园网实测](campus-browser/verification-summary.json) · [复核页验证](campus-access-summary.json)

受控测试覆盖首轮成功、失败后成功、连续退步、预算耗尽、澄清与恢复、错误格式重验、服务故障、局部保护、提交被拒绝以及丢失提交响应后的同 ID 轮询。远端历史记录与下载图像哈希见[部署实测凭据](../deployment/verified-summary.json)。
